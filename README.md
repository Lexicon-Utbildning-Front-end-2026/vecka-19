## 📅 Måndag: Avsluta och leverera

Vi går igenom vad det innebär att färdigställa ett projekt och flyttar fokus från nya features till leverans.

### Förmiddag: gemensam genomgång

- Definition of done (när något räknas som klart)
- Scope freeze
- Build, miljövariabler och deployment (publicering)
- Hur man förbereder en kort och stabil demo

### Eftermiddag: studentens eget arbete

- Färdigställ kärnflöden
- Flytta extrafunktioner utanför slutleveransen vid behov
- Börja säkra build, README och demo

### Att tänka på

- Kärnflödet ska fungera
- Viktiga fel ska vara hanterade
- Det ska inte finnas kända problem som blockerar demon
- Nya extrafunktioner ska bara läggas till om kärnan är stabil

### 🎯 Mål för dagen

* Bestämma vad som är klart nog
* Frysa scope (omfattning)
* Färdigställa kärnflöden
* Kontrollera build (färdigbyggd version)
* Börja med README

## 📅 Tisdag: Testa som användare

Eget arbete och avstämning. Testa projektet som användare, inte bara som utvecklare. Låt gärna någon i din närhet som inte jobbat med det testa också och få deras feedback. Ju närmare målgruppen och ju mer ovana de är, desto bättre.

### Eget arbete

- Testa huvudflödet som en ny användare
- Skriv ner problem och prioritera dem
- Rätta det som påverkar demon mest

### 🎯 Mål för dagen

* Testa huvudflödet
* Hitta trasiga delar
* Förbättra det viktigaste
* Rätta prioriterade problem
* Fortsätta README

---

## 📅 Onsdag: Feature freeze, QA och deployment

Kärnan fryses. Fokus ligger på kvalitet, tillgänglighet, felhantering och deployment där det är aktuellt.

### 🎯 Mål för dagen

* Sluta lägga till features
* QA (kvalitetskontroll) på kärnflödet
* Kontrollera felhantering
* Eventuellt bygga projektet i en ren miljö (klona från GitHub i ny mapp och kör)
* Testa eventuell deployment
* Rätta bara det som behövs för stabilitet och begriplighet - inget nytt ska göras nu!

---

## 📅 Torsdag: README och presentationsförberedelse

Vi färdigställer dokumentation och förbereder en kort, stabil demo. Gå gärna tillbaka till tidigare föreläsning om detta vid behov.

### README bör innehålla

- Problem och målgrupp
- Funktioner
- Skärmbilder, demo eller deploymentlänk om det finns
- Teknikval
- Lokal setup
- Kända begränsningar
- Möjliga nästa steg


### 🎯 Mål för dagen

* Skriva klart README
* Förbereda demon
* Repetera presentationen
* Ha en reservplan

---

## 📅 Fredag: Presentation

Presentationerna sker i halvklass på förmiddagen. Mötena för presentationerna startar kl 9.00 (OBS! Tidigare än vanligt!)

Varje person har mellan ca 5-10 minuter för sin presentation, inte kortare eller längre. Kortare frågor kan tas under eller efter varje redovisning i mån av tid.

**Deltagaren delar projektlänk** och eventuell deployment, visar funktionaliteten och beskriver sina viktigaste val och lärdomar. **Ingen kod ska visas**, däremot kan ni prata om hur ni löste saker under presentationen (t ex om ni gjort client components någonstans eller om ni valt en specifik databas, tredjeparts bibliotek eller dylikt).

### Presentationen/produkt-demon bör ta upp:

- Problem och målgrupp
- Projektets viktigaste funktion (kärnflödet)
- Centrala tekniska val
- Hur scope förändrades
- Hur AI användes och kontrollerades, om AI användes
- Största lärdomen
- (Vad nästa steg skulle vara)
